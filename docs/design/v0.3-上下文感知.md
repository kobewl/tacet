# v0.3「更懂时机」设计说明

> 本文是**实现级**文档，随代码走。规划级的范围与取舍见文档中心《版本路线图》与 ADR-012。

## 1. 数据流

```
每 10 秒 tick（apps/desktop/src/state.rs）
 │
 ├─ expire_do_not_disturb_if_due   定时勿扰到期 → 关开关并落库
 ├─ ContextEngine.sample           麦克风占用 → MeetingTracker → MeetingPhase
 ├─ WindowHints{in_meeting, outside_work_hours}
 └─ WindowPolicy.evaluate_with     窗口关闭 → Reason::InMeeting / OutsideWorkHours / DoNotDisturb …
        │
        └─ 窗口开着才进入 PolicyEngine，决定是否真的弹
```

Java 类比：`WindowPolicy` 像一串 `Filter`，任何一个说「现在不行」就短路并给出原因；
`MeetingTracker` 像带去抖与熔断器的状态机。

## 2. 会议检测

### 2.1 信号

读取 CoreAudio 的属性，**不录音、不打开麦克风、不申请任何权限**：

| 方式 | 属性 | 精度 |
| --- | --- | --- |
| 进程级（优先） | `kAudioProcessPropertyIsRunningInput`（遍历进程对象） | 精确：只有真的在采集的进程才算 |
| 设备级（回退） | 默认输入设备的 `kAudioDevicePropertyDeviceIsRunningSomewhere` | 粗糙：任何进程占用都算 |

运行时先探测进程级是否可用，不可用才回退设备级；用的是哪一种会写进能力说明。
**哪个 macOS 版本起有进程级属性我没有核实**，所以不按版本号判断，改为运行时探测。

### 2.2 MeetingTracker 状态机

```
Clear ──麦克风占用──► InCall ──释放──► Settling ──3 分钟无占用──► Clear
                         │                 │
                         │                 └─ 再次占用（静音/取消静音抖动）──► InCall
                         └─ 连续占用满 90 分钟 ──► GaveUp（放行，直到释放）
```

- **3 分钟会后缓冲**：会议刚结束人通常还在收尾；同时承担去抖（静音 / 取消静音会让占用短暂掉线）。
- **90 分钟保险丝**：某些后台程序会一直占着麦克风，没有保险丝的话提醒会被永久吞掉。
  这是对「误判」的兜底，宁可会议里多弹一次，也不让用户整天收不到提醒。

### 2.3 已知限制（如实记录）

- 设备级回退下，耳机 / AirPods 播放音频时可能被误判为「在占用」。进程级方式没有这个问题。
- 设备级回退只看**默认输入设备**，外接的非默认麦克风看不到。
- **正向用例（真的开了会）没有在自动化里验证**：采集需要系统麦克风授权，测试环境里无法稳定构造。
  已验证：本机（macOS 27.0.1）上进程级探测可用、空闲时为 `false`、播放音频时仍为 `false`。
  真实会议场景请在 Zoom / Teams / 腾讯会议里手动确认，并把结果回填到 CHANGELOG。
- 不读日历（EventKit 授权成本高、与「零权限」的产品承诺冲突）。

## 3. 定时勿扰

- `do_not_disturb`（开关）+ `do_not_disturb_until`（到期时刻，可空）；`dnd_active(now)` 统一判断。
- 选项：30 分钟 / 1 小时 / 2 小时 / 到明早 8 点 / 手动关闭。「到明早」的规则：今天 8 点还没到就用今天（凌晨 2 点说「到早上」指几小时后），否则用明天。
- **设置页保存偏好时不再读取 `doNotDisturb`**：设置页是「整份读出—改—整份写回」，
  若接收该字段，用户在设置页停留期间面板里开启/到期的勿扰会被陈旧值覆盖。勿扰只能通过 `set_do_not_disturb` 修改。
- 关闭勿扰时同时清掉期限，避免「开关关着、期限还在」的半截状态。

## 4. 工作时段

- `WorkHours{enabled, start_minute, end_minute, weekdays_only}`；默认关闭。
- 支持跨午夜（如 22:00–06:00）；起止相同按全天处理——细节见 `crates/tacet-core/src/model/prefs.rs` 的测试。
- 星期按本地日历计算，周一 = 0（`LocalOffset::clock_parts`）。

## 5. 「为什么没提醒」的判定顺序

以代码为准（`crates/tacet-health/src/window.rs` 的 `evaluate_with`、`crates/tacet-core/src/policy/mod.rs` 的 `decide_for`）：

1. **时机窗口（WindowPolicy）**：不在电脑前 → 非工作时段 → 会议中 → （紧急豁免到此为止）→ 刚打扰过 → 深夜。
   「不在」「非工作时段」「会议中」排在紧急豁免**之前**：需求拉满也不能无视用户划的边界与场合。
2. **决策引擎（PolicyEngine）**：休息中 → **勿扰** → 需求没到阈值 → 同类冷却 → 其余规则（见源码）。
   勿扰在 tick 开头先做一次到期检查，到期则当拍恢复，所以决策引擎看到的开关始终是新的。

静默的理由都会写进决策，面板 / 询问页 / 日志能查到。
