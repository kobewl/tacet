# Tacet v0.1 · 高保真原型

## 设计定位

Tacet（拉丁语「休止」）的核心体验主张是：**提醒存在，但不占据注意力**。视觉语言必须让「打扰」这件事显得克制、体面、可被信任。

因此这一版放弃了实体卡片式的重 UI，改为：

- **底层是一层柔和的光晕桌面**（冷暖交替的多点径向渐变），模拟真实 macOS 桌面透出的环境光；
- **上面盖一层全屏白色毛玻璃**（`rgba(255,255,255,.30)` + `saturate(210%) blur(52px)`），让所有内容都像浮在一层通透的雾面上；
- **再叠顶光与中心提亮**，制造玻璃的「厚度感」而不是廉价的高斯模糊；
- **四周极轻地压暗收边**，避免大面积白色发飘。

主色只有一支：深青 `#0C6E66`（按钮用 `#127F76 → #0C6E66` 的微渐变）。四类健康（休息 / 喝水 / 活动 / 护眼）各用一个低饱和的功能色，只出现在图标底座和状态数字上，绝不铺面积。

8 屏完整界面原型，主设计语言为**全屏白色毛玻璃（white frosted glass）**。

## 动效设计：为什么不做「动起来的背景」

这一版有两处动效，都是在查过资料之后才决定这么做的。

### 结论先说：背景不要动

查证结果（American Academy of Ophthalmology 的计算机使用指南、WCAG 2.3.3）：

- **屏幕运动本身对眼睛没有好处。** AAO 列出的数字眼疲劳成因是：眨眼频率下降（正常约 15 次/分，盯屏时只剩 5–7 次）、干眼、眩光、亮度对比失配、姿势不良。**画面运动不在其中。** 所以「让背景动起来对眼睛更好」这个说法，在眼科上没有依据。
- **反过来，背景运动会抢注意力。** 运动是周边视觉的强刺激，会自动捕获注意 —— 对一个核心主张是「提醒存在，但不占据注意力」的产品来说，这是反向的。
- **还可能引起不适。** WCAG 2.3.3 明确要求由交互触发的非必要动画必须可以关闭，理由是可能诱发前庭障碍者的眩晕、恶心、头痛。

所以背景保持静止。真正对眼睛有帮助的两件事是**看向远处**和**眨眼**，它们被做成了 02 屏的行动清单，而不是做成动画。

### 那动效放在哪里：服务于「让用户离开屏幕」

只做了两个，且都服务于同一个目的 —— 把注意力从屏幕引开。

**1. 呼吸引导环（02 屏）** — 这是主动效

内圈做 10 秒一个周期的缩放（4 秒吸 / 6 秒呼，即 6 次/分），幅度 **5%**。旁边配「吸气 4 秒 / 呼气 6 秒」文案同步切换。

依据是慢呼吸（<10 次/分）能引起自主神经系统的变化、促进放松（Zaccaro 等 2018 年的系统综述）。需要说明：**这个证据基础不算强**（只有少数综述，没有大规模 RCT），所以它是设计上的合理选择，不是「临床证实」。

幅度定在 5% 是实测后的取舍：最初用 3.8%，在 27 寸屏上几乎看不出来，起不到引导作用；5% 是「余光能明确跟上、但不会觉得画面在晃」的平衡点。（实测采样：最小 1.0001 / 最大 1.0496，即 4.9%。）

尺度上仍然刻意压得很小 —— 够被余光感知、引导呼吸，但不足以把人留在屏幕前盯着它看。

**2. 倒计时进度环（02 屏）** — 这是信息型

外圈随剩余时间匀速收缩，走完一圈正好休息结束。它回答的是「还剩多久」，不是装饰。

### 顺带说明：01 屏刻意没有环

01 屏是「询问」——要不要休息。这一屏已经有标题、倒计时、理由、操作四层信息，再加一个环只会互相打架。进度环留给 02 屏，那时用户已经接受休息，关心的才是「还剩多久」。

### 真实输入态（03 屏）

输入框如果只是个静态方块，评审时没法判断「敲字是否舒服」。所以 03 屏做了三件只有在真机上才看得出来的事：

1. **真光标闪烁** — 用 `steps(1, end)` 而非 `ease`，因为系统光标是硬切换不是渐隐，节奏对齐 macOS（约 1.06s）。
2. **聚焦环呼吸** — 4.2 秒一个极慢的明暗周期，暗示「这里在等你说话」。不抢戏，但让静止页面有生命感。
3. **完整状态** — 已输入文字 + 字符计数（12/100）+ 清除按钮 + `↵` 保存提示。

### 关于 `prefers-reduced-motion`

所有动效都做了关闭分支（`.pulse` / `.cd` / `.prog` / `.caret` / `.field`）。用户在系统里开了「减少动态效果」，页面就完全静止。这是 WCAG 2.3.3 的要求，也是这类产品应有的基本尊重。

## 异常态：两屏，但其中一屏刻意「不做」

原始需求里提到「AI 未配置时的降级提示」。**这一屏没有做成提示，而是做成了对照页** —— 理由是它和产品原则直接冲突：

> 原则 7 / F8.8：未配置 AI 时，此入口**静默存在**，无红点、无提示、不阻塞任何流程。

如果为「AI 未配置」弹一个降级提示，就等于在用户没打算用 AI 的时候提醒他「你没配 AI」—— 这恰恰违背了「AI 完全可选」。所以 10 屏做成左右对照：未配置 / 已配置两种状态下，提醒体验逐条列出并证明**完全一致**，唯一差别只是设置页里一行状态文字。它是给评审看的「原则证明页」，不是产品界面。

另一屏（09）是真的异常态，而且很值得看：**连续跳过三次后的主动收手**。

设计上有一个关键取舍：**收手不能做成全屏宣告**。用户已经连跳三次，说明他此刻有明显更重要的事；这时候弹一个全屏告诉他「我要收手了」，本身就是第四次打扰 —— 用一个打扰去承诺不再打扰，逻辑上自相矛盾。所以收手只用一条系统通知（Level 2），说完就彻底安静。

同时这一屏把「不会发生的事」逐条列了出来：不扣分、不降权重、不追问。因为「不惩罚」这件事，只有说清楚才可信。

## 休息时的那句话：为什么是本地池 + API，而不是直接调 API

需求是「接一个免费的 API，可以变化的」。实测下来，**没有一个免费名言 API 能稳定提供励志内容**：

| 源 | 结果 |
|---|---|
| 一言 hitokoto | 可用，但库以诗词、文学、网易云评论为主 |
| vvhan / 52vmy / oick / tenapi / xygeng | 无响应或返回 HTML 页面，不可用 |

一言的实测问题（都是真实拉到的内容）：

- `苟利国家生死以，岂因祸福避趋之` — 林则徐，需要动脑子
- `不要说我一无所有，我们要做天下的主人` — 《国际歌》，情绪动员
- `梦想还是要有的，万一见鬼了呢` — 抖机灵，不是励志
- `希望とシェイクハンドして。` — 日文，中文界面里出戏
- `生不由己，不如不生` — 出现在休息场景是灾难

加上语种、长度、气质过滤后，**命中率只有 2% 左右（60 条过 1 条）**。为了凑够句子去循环拉取，等于对免费 API 发几百次请求，既不礼貌也不可靠。

所以最终方案：

- **本地精选 61 条**负责稳定输出。一次休息只显示一句、每次进入从随机位置开始，「每次都不一样」由池子本身保证。
- **API 只做低频点缀**：每次最多探 3 次，命中就用（约每 4 次换句掺 1 条），不命中就用池子。
- **过滤条件**：长度 8–26 字、通过励志关键词白名单、排除负面词、排除日文/西里尔/纯英文、排除无出处或出处为「网络」的。

这样既有「活的内容」的新鲜感，又不会在劝人休息的界面上出现不合适的句子。

### 实现时的调整：API 那一半没有搬过去

正式代码（`packages/ui/src/quotes.ts`）只搬了**本地句子池**，砍掉了 API 探测。
原因有两个，都是原型阶段看不到的：

1. **隐私立场**：休息界面是全屏覆盖的，在「劝你休息」的界面上发外部网络请求，
   等于告诉用户「这个帮你专注的工具在自己联网」。产品原则里没有比这更贵的代价。
2. **收益太小**：API 的定位本来就只有「每 4 次换句掺 1 条」（约 25% 的句子），
   命中率 2% 意味着大部分探测都是白跑。为一成的惊喜感换一个联网行为，不划算。

池子按同样的选句标准收敛到 57 条（原 61 条里去掉了四条带负面意象或亏欠感的 ——
「所有的失去，都会以另一种方式归来」里有「失去」，「别让明天的你，讨厌今天的自己」
和「将来的你，一定会感谢现在拼命的自己」带着「你欠了未来的自己」的压力，
「愿你在不幸中学会慈悲」里有「不幸」）。这个产品的立场是「休息是应得的」，
不是「休息完了要更努力地还债」，所以这类句子一律不要。

## 另一个实现期的修正：`backdrop-filter` 在桌面应用里是假的

原型里那层「白色毛玻璃」是用 `backdrop-filter: blur(52px)` 做的，在浏览器里
能真的把背后的桌面糊掉 —— 但**打包成 Tauri 应用之后就不生效了**：

Tauri 的透明窗口是一个没有背景色的 WKWebView，`backdrop-filter` 能采样到的
只有**同一个网页内部**画在它下层的内容，窗口背后的桌面和应用窗口都不在
网页的光栅化范围里。结果是一点都不模糊，只剩一层半透明白粉刷在屏幕上 ——
用户看得清自己的代码和浏览器标签，只是全部褪了色，看起来像显示器坏了。

修正方式是各走各的路：

- **全屏休息屏**：改成自绘的柔和渐变（色相取自原型里给毛玻璃打光的那组
  「桌面光源」）。做成不透明之后，无论用户背后开着什么、用哪块显示器，
  这一屏在每台机器上都长得一样。
- **菜单栏面板**：改用 macOS 原生材质 —— `tauri.conf.json` 里的
  `windowEffects: { effects: ["popover"] }`，由 NSVisualEffectView 提供
  真正的模糊。CSS 那边只留半透明白底和高光边框。

这个坑记在 `packages/ui/src/views/BreakFlow.css`、`styles/global.css` 和
`styles/tokens.css` 的注释里，避免以后再有人写一遍 `backdrop-filter`。

## 多显示器：原型里没画、实现时必须补上的一块

原型是全屏覆盖的，所以没有触及「用户接了第二块屏怎么办」这个问题。
实现时发现这直接决定功能成不成立：**只盖一块屏的「全屏休息」是假的** ——
用户把鼠标移过去就能继续干活，休息被绕过去了。

### 时机：先问，再做

覆盖**所有**屏幕这件事分两步发生，界线划在用户按下「现在休息」的那一刻：

| 阶段 | 覆盖范围 | 理由 |
|---|---|---|
| 提醒刚弹出（询问） | 只有鼠标所在那块屏 | 用户还没同意休息，他可能要点「3 分钟后」。此刻糊掉他的副屏是纯粹的冒犯 |
| 用户点了「现在休息」 | 所有屏幕 | 他刚刚明确表达了意愿，挡住其它屏是履行承诺 |

这条界线是「提醒」和「绑架」的分界。**早期实现里这两件事是混在一起的**
（都在 `show_break_window` 里），改的时候特意拆成 `show_break_window`
与 `show_break_veils` 两个函数，并把各自的理由写在函数注释里 ——
否则下一个人很容易「顺手合并」回去。

### 形态：副屏是幕布，不是第二套界面

副屏不显示完整的休息流程（倒计时 + 按钮 + 待办输入），只显示一层安静的白雾
和一句「还剩多久」。两个理由：

1. **状态会打架**：多个窗口各自维护阶段，用户在副屏点「跳过」，
   主屏还停在询问态 —— 界面互相打脸，后端还会收到两次矛盾的操作。
2. **注意力被摊薄**：用户不知道该看哪块屏，视线在屏幕之间跳。
   而这一屏的全部目的是让他**离开**屏幕。

所有操作集中在主屏。副屏留的出口是单击（意图转发给主窗口处理），
Esc 由主窗口接管 —— 键盘焦点自始至终没有离开主屏。

### 三个实现上必须小心的点

1. **幕布绝不能抢键盘焦点**。macOS 上显示窗口走的是 `makeKeyAndOrderFront`，
   会把窗口设为 key window。而幕布恰恰是在用户要点「接下来准备做什么」
   输入框的那一刻创建的 —— 抢了焦点，用户就打不了字，还完全不知道为什么。
   解法是 `.focusable(false)`（它让 `canBecomeKeyWindow` 返回 NO，
   窗口能显示但不能成为 key window）。

2. **主窗口和幕布必须同生共死**。只关主窗口会让副屏继续糊着白雾，
   用户不知道该点哪里才能恢复 —— 比不休息更糟。所以 `hide_break_window`
   把两者一起收，另外还在调度线程的每次 tick 里核对一次这条不变量
   （正常路径覆盖不了 webview 崩溃之类的意外）。

3. **隐藏窗口不会卸载网页**。窗口再显示时 React 组件还停在上次离开的阶段：
   上次休息正常结束后停在「欢迎回来」，下次提醒弹出来就会错误地显示它。
   所以每次「从隐藏变显示」都广播一个 `breakShown`，前端按真实状态重置阶段。
   要注意别把「用户在流程中间再次触发」也误判成重新打开 ——
   那会让刚点完「开始休息」的用户又被问一次要做什么。

这些决定写在 `apps/desktop/src/windows.rs` 和 `packages/ui/src/views/BreakVeil.tsx`
的注释里。相关的纯逻辑（哪块屏该盖）有单元测试：`Monitor` 在测试里没法构造，
所以把它抽成了只吃「位置 + 尺寸」的纯函数。

### 导入时的四个坑（改写 HTML 时注意）

Ardot 的 HTML 转换器会**先把页面里的外链资源全部下载一遍**，有四类写法会让转换失败或走形：

1. **内联 `data:image/svg+xml` 的噪点纹理**会被当成外部资源去下载，导致整体 `Download failed`。
   本版已改用叠层半透明点阵（`radial-gradient` + `background-size`）近似颗粒质感。
2. **SVG 必须写死 `width` / `height` 属性**。转换器不推断 SVG 固有尺寸，缺省时会把图标拉伸变形。
3. **绝对定位 + `transform: translateX(-50%)`、负 `margin`、过窄的自动宽度**容易让文本逐字换行。
   优先用 flex 布局；给关键文本留足宽度。同理，**不要用全角空格（`　`）做间隔** ——
   转换器会把它吃掉，导致两个元素挤成一行；要用 `gap` 或 `margin`。
4. **不要用键盘发送数字给 Ardot 画布**。Ardot 里数字键 `0`–`9` 是「设置不透明度」的快捷键。
   曾在自动化时用 CDP 发过一个数字键，把当时选中的图层全部设成了 12% 不透明度，
   表现为「原型图整体发灰」。凡是通过键盘驱动 Ardot，都要先确认焦点不在画布上。
   脚本化编辑应一律走 MCP 的 `batch_edit`，不要模拟键盘。

（第 4 条曾真实造成 5 屏发灰，排查方式：读顶层 Frame 的 `opacity` 属性 ——
若是 0.12 且子节点都是 1，即可确认是这个原因，用 `U("<id>", {opacity: 1})` 恢复。）
